# 截断奖励与部分得分

[手册目录](index.md) · [相关：吞吐测量与对照实验](throughput.md)

比较生成吞吐时，最大输出长度会影响截断率。截断样本如何计分，又会改变学习信号。TorchTitan 在提交 `1fdf045` 把 `truncation_reward` 换成 `truncation_penalty`，可以先计算样本的部分得分，再减去固定惩罚。本文核对这一提交，配置迁移需要同时核对使用的源码版本。 [上游 PR #5451](https://github.com/pytorch/torchtitan/pull/5451)

## 固定奖励与扣分分别怎样影响排序

假设任务按测试通过比例给分。一条截断回答通过了八成测试，另一条通过两成。如果把所有截断回答的奖励固定设为 0，两条样本得到相同结果。采用 0.2 的固定扣分后，两条样本分别得到 0.6 和 0，部分得分之间的差距得以保留。对于相同的原始分数，截断回答会比正常结束的回答少 0.2。 [Rubric 评分实现](https://github.com/pytorch/torchtitan/blob/1fdf04562e7bb02d8df9202a269668b43c42f503/torchtitan/rl/rollout/rubric.py)

## 惩罚在权重归一化之后减去

设内容评分为 0.8、格式评分为 0.5，两项权重分别为 3 和 1。Rubric 先用归一化权重求和，再对截断样本扣分。

| 计算环节 | 结果 |
| --- | --- |
| 内容贡献 | `3 / 4 × 0.8 = 0.6` |
| 格式贡献 | `1 / 4 × 0.5 = 0.125` |
| 合成得分 | `0.6 + 0.125 = 0.725` |
| 截断惩罚为 0.2 时的最终奖励 | `0.725 − 0.2 = 0.525` |

如果把惩罚也除以权重和，就会算成 0.675，与这一版本的实现不符。`reward_breakdown` 记录各奖励函数的原始分数和正数惩罚，复算最终奖励时要先应用各自权重，再扣惩罚。上游测试用单个权重为 2 的奖励函数检查这一点。 [权重计算与测试](https://github.com/pytorch/torchtitan/blob/1fdf04562e7bb02d8df9202a269668b43c42f503/tests/rl/unit_tests/cpu/test_rubric.py)

## 对照实验里一起记录什么

保存最大生成长度、最大轮数、截断状态、`rollout/truncation_rate`、惩罚值和奖励分量。惩罚默认值为 0，负数配置会被拒绝。错误状态走 `error_reward` 的处理路径，设置惩罚前要核对任务的终止条件。 [配置与状态判断](https://github.com/pytorch/torchtitan/blob/1fdf04562e7bb02d8df9202a269668b43c42f503/torchtitan/rl/rollout/rubric.py)

如果两次运行的截断率分别为 10% 和 30%，惩罚均为 0.2，仅这一项对平均奖励的直接扣减分别为 0.02 和 0.06。这个手算假设每条样本等权且其他评分不变。观察奖励变化时，把任务原始得分和截断惩罚一起看，才能解释长度限制带来的影响。

迁移到这个提交后，旧的 `truncation_reward` 字段会导致配置构建失败，需要按任务目标重设评分方式。验证也使用同一个 rubric，因此惩罚会影响验证得分。本页完成公开源码与算例核对，真实 RL 训练待验证。 [迁移说明](https://github.com/pytorch/torchtitan/pull/5451)
